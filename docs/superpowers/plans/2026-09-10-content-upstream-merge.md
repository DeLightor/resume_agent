# US-33 内容级上游合并实施计划

**目标：** 让父节点的工作经历、项目、技能和个人信息变更可在直接子节点中逐项审阅，并保住子节点自己的改动。

**架构：** 每个子节点保存直接父节点的共同基准。父节点写入后，以基准、父内容和子内容生成三方差异；每项接受或保留都会推进该项基准。SSE 仅通知客户端刷新权威状态，草稿存储层负责保住未保存内容。

**约束：** SQLite 增量迁移；所有确认携带子节点 If-Match 和展示时的父版本；软删除节点不参与；不新增依赖。

## 实施任务

- [x] 用测试定义三方字段、bullet、条目增删、冲突和拒绝后的不重复提示。
- [x] 实现 `content_merge`：经历按 company+role、项目按 name 对齐；身份重复时降级为整段确认。
- [x] 增加共同基准、来源节点和来源版本迁移；新节点从父节点建立基准，旧节点从首次扫描开始跟踪。
- [x] 用同一 SQLite 事务保存内容、历史、待处理项和更新后的基准；过期父/子版本返回 409。
- [x] 在节点编辑、个人信息、撤销/重做和 Agent 写入后传播直接子节点更新。
- [x] 加入提交后可见的 SSE 树更新流，连接和重连都先发出权威状态刷新信号。
- [x] 用统一审阅卡展示当前、上游和冲突基准，逐项采用/保留；冲突时禁止“全部接受”。
- [x] 运行后端、前端、OpenSpec、lint/build 和浏览器验收。

## 风险控制

父节点在用户审阅期间再写入时，来源版本不一致会拒绝确认，不覆盖任何内容。SSE 不传送简历正文，客户端收到事件后读取服务端；若本地草稿未保存，草稿层保留它并显示冲突。
